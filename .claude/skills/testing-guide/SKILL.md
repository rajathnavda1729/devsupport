## Steps
1. **Discover what actually exists.** Look for:
   - package scripts and Makefile targets;
   - docker-compose services;
   - test directories;
   - CI config;
   - `.env.example`.

   Use the real commands. If something does not exist yet, write the intended command and mark it `(to be created in T-xxx)`, linking the tracker task.
2. **Prerequisites and setup.** Give copy-pasteable commands. A new developer should go from clone to green tests by following this section alone.
3. **Test data.** Cover the fixtures and seeds, how to reset state, and how to create edge-case data for the CRITICAL requirements.
4. **Test pyramid table.** For each layer, give the scope, framework, location and command. Unit tests cover domain logic. Integration tests cover adapters, the DB and queues. Contract tests cover the APIs consumed and provided. End-to-end tests cover only the critical journeys. Performance tests run through `bench.py`.
5. **Log watching.** Explain how to run `devkit/tools/logwatch.py` alongside the tests, using the profile generated by the `log-watcher` skill. For each key flow, list the log lines that prove success and the ones that indicate failure.
6. **Manual and exploratory checks.** Give a checklist with expected results.
7. **Debugging tips.** Cover the common failures and their fixes, debugger attach steps, and useful DB or queue inspection commands.
8. **CI.** Say which suites run on PR versus nightly, and which gates block a merge (tests, coverage, `bench.py compare`, `logwatch --fail-on ERROR`).

Verify every command you write. Run it if you can; otherwise mark it "unverified".
